# PRD: AI 동화책 제작 + 캐릭터 3D 프린팅 앱

- 문서 버전: v0.2 (아이 사용자 기준 개정: 디자인 컨셉·접속 방식 추가)
- 작성일: 2026-11-05 / 개정: 2026-11-06
- 작성 대상: wow3d (3D프린팅 서비스 운영사)
- 상태: 검토 요청

> **v0.2 주요 변경:** 이 서비스는 **아이들이 직접 접속하는 사이트**라는 전제로 개정했습니다. 8장 디자인 컨셉, 9장 접속 방식(부모 계정·아이 프로필·로그인 방법·보호 장치)을 새로 넣었고, 페르소나·비기능 요구사항·로드맵을 아이 안전 기준으로 보강했습니다.

## 1. 한 줄 요약

아이가 직접 접속해 부모와 함께 AI로 나만의 동화책(그림책·웹툰)을 만들고, 컴퓨터·태블릿·모바일에서 읽은 뒤, 책 속 캐릭터와 사물을 클릭 한 번으로 3D 모델로 미리 보고 **wow3d pro(wow3dpro.co.kr)** 를 통해 실물 피규어로 받아보는 서비스. 아이는 **만들고 읽고 구경하는** 역할, 부모는 **관리하고 결제하는** 역할로 화면과 권한을 나눈다.

> "읽는 책"에서 "손에 쥐는 책"으로. 이야기 → 그림 → 3D → 실물까지 한 앱에서 끝낸다.

## 3. 배경과 문제 정의

### 3.1 시장 배경
- 생성형 AI(텍스트·이미지)로 개인 맞춤 동화책을 만드는 수요가 빠르게 늘고 있음.
- 이미지→3D 생성 AI(Meshy, Tripo, Hunyuan3D, TRELLIS 등)가 상용 품질에 도달해, 일반인도 사진·그림 한 장으로 3D 모델을 얻을 수 있게 됨.
- 그러나 **"만든 3D 모델을 실제로 출력 가능한 상태로 다듬고, 출력하고, 배송받는" 과정**은 여전히 일반 부모에게 높은 진입장벽.

### 3.2 사용자 문제
| 문제 | 현재 대안의 한계 |
|---|---|
| 아이에게 딱 맞는 책(이름·취향·교육 주제)을 구하기 어렵다 | 시판 동화책은 획일적, 맞춤 출판은 비쌈 |
| AI 도구는 많지만 글·그림·편집·전자책 저장을 따로 해야 한다 | ChatGPT + 이미지 생성 + 편집툴 + 뷰어를 오가야 함 |
| 화면으로만 보는 책은 아이의 몰입·기억이 약하다 | 실물 연계(굿즈, 만들기 활동) 없음 |
| 3D 프린팅은 관심 있어도 모델링·출력 방법을 모른다 | 이미지→3D 서비스는 결과물만 줄 뿐 출력 가능성 검증·주문이 없음 |

### 3.3 wow3d 관점의 기회
- 3D프린팅 업체가 **수요(캐릭터 피규어 주문)를 직접 만드는 앱**을 보유 → 출력 주문의 안정적 유입 채널.
- 동화책 앱은 무료/저가로 사용자를 모으고, **실물 피규어 출력이 핵심 수익원**이 되는 구조.

## 4. 목표와 성공 지표

### 4.1 제품 목표
1. 부모가 **15분 안에** 아이 맞춤 그림책 1권(8~16쪽)을 완성할 수 있다.
2. 완성된 책을 **웹·태블릿·모바일 어디서나** 읽고, 오프라인으로도 볼 수 있다.
3. 책 속 이미지를 클릭하면 **1~3분 안에** 3D 프리뷰를 볼 수 있다.
4. 3D 프리뷰에서 **3번의 탭 이내로** wow3d pro에 출력 의뢰가 접수된다.

### 4.2 핵심 지표 (KPI)
| 구분 | 지표 | MVP 목표(출시 3개월) |
|---|---|---|
| 활성 | 월간 책 생성 수 | 3,000권 |
| 완성률 | 책 생성 시작 → 완성 비율 | 60% 이상 |
| 재방문 | 생성 후 7일 내 재열람률 | 40% 이상 |
| 3D 전환 | 완성 책 중 3D 프리뷰 실행 비율 | 30% 이상 |
| 매출 전환 | 3D 프리뷰 → 출력 주문 전환율 | 5~8% |
| 품질 | 출력 주문 중 재작업/불량률 | 3% 이하 |

### 6.1 경쟁/유사 서비스

| 서비스 | 유형 | 강점 | 한계 |
|---|---|---|---|
| **Storybird** | 그림책·스토리 창작 플랫폼 | 고품질 일러스트 라이브러리, 교육 시장 | 기존 그림 조합 방식, AI 맞춤 약함, 한국어·3D 없음 |
| **Book Creator** | 교육용 전자책 저작 도구 | 학교 도입 많음, 멀티미디어 편집 | 콘텐츠를 사용자가 직접 다 만들어야 함, AI 생성·3D 출력 없음 |
| **Storybook(Gemini), Oscar, StoryBee 등 AI 동화 앱** | AI 동화 생성 | 빠른 텍스트+그림 생성 | 일회성 읽기 위주, 편집·웹툰·실물 연계 없음 |
| **Wonderbly 등 맞춤 동화 출판** | 이름 넣은 인쇄책 | 실물 책 선물 수요 | 템플릿 고정, 비쌈, 디지털·3D 없음 |
| **Meshy / Tripo / Hunyuan3D** | 이미지→3D 생성 AI | 빠른 3D 생성 품질 | 전문가·크리에이터 대상, 출력 가능성(두께·지지대) 검증 없음, 주문·배송 없음 |
| **Shapeways / 국내 3D출력 대행** | 3D 출력 주문 | 출력 품질 | STL 파일을 사용자가 준비해야 함 |

### 6.2 토이북만의 차별점

1. **이야기 → 3D → 실물까지 원스톱**
   경쟁 서비스는 "책 만들기" 또는 "3D 만들기" 중 하나만 한다. 토이북은 책 속 캐릭터를 그대로 클릭해 3D로 만들고 출력까지 주문한다. 이 흐름을 가진 서비스는 사실상 없다.

2. **출력 가능성을 보장하는 3D 파이프라인 (wow3d의 제조 노하우)**
   일반 이미지→3D 결과물은 얇은 부위, 뜬 부품, 구멍 난 메쉬 때문에 그대로 출력하기 어렵다. 토이북은 **자동 메쉬 수리, 최소 두께 보정, 받침대 자동 생성, 출력 크기별 견적**을 거쳐 "출력 가능한 모델"만 주문으로 넘긴다. 3D프린팅 업체가 직접 운영하기 때문에 가능한 차별점.

3. **캐릭터 일관성 (Character Consistency)**
   한 권 안에서, 그리고 시리즈 전체에서 같은 캐릭터가 같은 모습으로 나오도록 "캐릭터 카드"를 저장하고 재사용. 이 캐릭터 카드가 그대로 3D 모델의 기준 이미지가 되어 **책 속 모습 = 피규어 모습**이 된다.

4. **아이 그림을 주인공으로**
   아이가 종이에 그린 그림을 찍으면 AI가 같은 스타일의 삽화로 확장하고, 그 캐릭터를 3D 피규어로 출력. 아이가 "내가 만든 캐릭터"를 손에 쥐는 경험.

5. **그림책 + 웹툰 두 가지 형식**
   유아용 그림책(1쪽 1장면)과 초등용 웹툰(컷 분할·말풍선·세로 스크롤)을 같은 이야기에서 전환 가능.

6. **부모-아이 공동 학습 설계**
   읽기 모드에 TTS 낭독(부모 목소리 녹음 가능), 단어 하이라이트, 독후 퀴즈, 교육 주제 템플릿(생활습관, 감정, 과학, 한글·영어) 제공.

7. **한국어·한국 교육과정 최적화 + 국내 출력·배송**
   한국어 자연스러운 동화체, 누리과정 주제 템플릿, 국내 배송과 빠른 출력.

## 7. 핵심 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = 출시 직후, **P2** = 확장

### 7.1 기능 1: AI e-book 생성 (그림책·웹툰)

#### 사용자 흐름
1. 책 만들기 시작 → 아이 정보(이름, 나이, 좋아하는 것) 입력
2. 주제 선택(템플릿) 또는 자유 입력 ("우리 아이가 양치를 싫어해요")
3. 형식 선택: 그림책 / 웹툰, 쪽수(8·12·16), 그림체(수채화, 크레파스, 3D 애니, 지브리풍 X → 저작권 안전 스타일만)
4. AI가 줄거리 개요 제안 → 부모가 수정·승인
5. 캐릭터 카드 생성(주인공·조연 외형 확정)
6. 페이지별 글 + 삽화 자동 생성
7. 페이지 편집기에서 글·그림 수정, 재생성, 이미지 업로드
8. 표지 생성 → 저장 → 서재에 등록

### 7.2 기능 2: 이미지 클릭 → 3D 모델 변환 (프리뷰)

#### 사용자 흐름
1. 책 페이지에서 캐릭터/사물을 길게 누르거나 "3D로 보기" 버튼 클릭
2. AI가 이미지에서 대상을 자동 분리(배경 제거) → 부모가 대상 선택 확인
3. (선택) 캐릭터 카드 기준으로 정면·측면·후면 뷰 자동 생성(멀티뷰)으로 품질 향상
4. 이미지→3D 생성 (진행 상태 표시, 완료 시 알림)
5. 3D 뷰어에서 회전·확대, 색상 미리보기, **AR로 책상 위에 놓아 보기**
6. "출력 가능성 검사" 결과 표시 → 출력 크기 선택 → 견적 확인 → 주문(기능 3)

#### 기능 목록
| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| D-01 | 대상 선택·배경 제거 | P0 | 클릭 지점 기준 객체 분할(SAM 계열) |
| D-02 | 이미지→3D 생성 | P0 | 외부 API(Meshy/Tripo) 우선, 자체 모델(Hunyuan3D/TRELLIS) 병행 검토 |

### 7.3 기능 3: wow3d pro 연동 3D 프린팅 출력 의뢰

#### 사용자 흐름
1. 3D 프리뷰 화면에서 "피규어로 받기" 선택
2. 옵션 선택: 크기(5/8/12cm), 재질·방식(FDM 단색, 레진 고정밀, 풀컬러), 마감(무도색/도색/색칠놀이 키트), 받침대 각인 문구
3. 실시간 견적(모델 부피·지지대량·옵션 기반)과 예상 제작·배송일 표시
4. 결제 → wow3d pro 주문 생성
5. 주문 상태 추적: 접수 → 출력 검수 → 출력 중 → 후가공 → 배송 → 완료
6. 배송 완료 후 "피규어 사진 찍어 책에 넣기" (책 마지막 장 자동 추가)

#### 기능 목록
| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| P-01 | 출력 옵션·견적 | P0 | wow3d pro 견적 API 호출 또는 앱 내 견적 규칙 엔진 |
| P-02 | 주문 생성 | P0 | 출력용 파일(STL/3MF) + 썸네일 + 옵션을 wow3d pro로 전송 |
| P-03 | 결제 | P0 | 토스페이먼츠/포트원 연동, 카드·간편결제 |
| P-04 | 주문 상태 추적 | P0 | wow3d pro 웹훅 수신, 앱 푸시·알림톡 |
| P-05 | 작업자 검수 단계 | P0 | wow3d 작업자가 출력 전 모델 확인·수정·승인 (불량 방지) |
| P-06 | 색칠놀이 키트 | P1 | 흰색 무도색 피규어 + 물감 세트 (부모-아이 공동 활동) |
| P-07 | 책+피규어 세트 | P1 | 인쇄책과 캐릭터 피규어 선물 패키지 |
| P-08 | 단체 주문 | P2 | 유치원·학교 반 단위 주문, 기관 결제 |
| P-09 | 오프라인 체험 연계 | P2 | wow3d 매장/체험 교실 예약 |

#### wow3d pro 연동 방식 (확인 필요)
wow3d pro(wow3dpro.co.kr)의 현재 API 제공 여부에 따라 단계별로 진행한다.

| 단계 | 방식 | 설명 |
|---|---|---|
| 1단계 (빠른 출시) | **주문 대행형** | 앱이 주문·결제를 받고, 출력 파일과 주문서를 wow3d pro 관리자 화면(또는 이메일/공유 드라이브)으로 전달. 상태는 관리자가 앱 백오피스에서 수동 갱신 |
| 2단계 | **REST API 연동** | wow3d pro에 주문 API(견적/주문 생성/상태 조회) + 웹훅 추가. 앱과 실시간 연동 |
| 3단계 | **생산 자동화** | 주문 파일을 슬라이서·프린터 큐로 자동 배정, 출력 진행률(사진/타임랩스)을 앱에 전송 |

최소 API 명세(2단계 기준, 안):
```
POST /api/v1/quotes          # 모델 파일 URL + 옵션 → 가격, 제작일
POST /api/v1/orders          # 견적 ID + 결제 정보 + 배송지 → 주문번호
GET  /api/v1/orders/{id}     # 주문 상태 조회
Webhook  order.status_changed  # 접수/검수/출력/후가공/배송/완료
```

## 8. 디자인 컨셉

### 8.1 컨셉: "책 속으로 들어가는 놀이터"
사이트 전체를 **하나의 그림책 세계**로 꾸민다. 아이는 메뉴를 고르는 것이 아니라 **장소를 찾아가는** 느낌으로 기능을 쓴다.

| 장소(화면) | 실제 기능 | 연출 |
|---|---|---|
| 🏠 **우리 집 책장** (홈) | 내 서재, 최근 책 | 나무 책장에 내 책 표지가 꽂혀 있고, 누르면 책이 튀어나와 펼쳐짐 |
| 🎨 **이야기 공방** | 책 만들기 | 작업대 위 붓·크레파스·마법 지팡이. 마스코트가 질문하며 함께 만듦 |
| 📖 **동화 극장** | 책 읽기·낭독 | 무대 커튼이 열리며 책이 펼쳐짐, 낭독 중 글자가 하이라이트됨 |
| ✨ **마법 상자** | 이미지 → 3D 변환 | 그림을 상자에 넣으면 3D 캐릭터가 튀어나옴 (대기 시간을 애니메이션으로 채움) |
| 🧸 **장난감 공장** | 출력 의뢰(부모 승인 필요) | 컨베이어 벨트로 내 캐릭터가 만들어지는 모습, 주문 진행 단계를 공장 단계로 표시 |
| 🏅 **스티커 도감** | 보상·독후 활동 | 책을 읽거나 퀴즈를 풀면 스티커 획득 |

### 8.2 마스코트
- 책과 3D프린터를 합친 캐릭터 1종 (예: 책 모양 몸에 노즐 모자를 쓴 꼬마 로봇 **"토비"**).
- 역할: 길 안내, 음성 안내, 칭찬, 대기 시간 놀아주기, 실수했을 때 "괜찮아, 다시 해 보자" 안내.
- 마스코트를 wow3d에서 피규어로 출력해 **가입 기념 굿즈·체험 교실 교구**로 활용 (브랜드 인지도).

### 8.3 비주얼 가이드
| 항목 | 가이드 |
|---|---|
| 색상 | 따뜻한 파스텔 기본(크림 배경, 하늘·민트·살구·레몬), 강조색은 채도 높은 1색(주황). 눈부심 방지를 위해 순백·형광색 배경 쓰지 않음. 잠자리 모드는 남색 계열 |
| 형태 | 모서리가 둥근 큰 카드와 버튼, 손그림 느낌 테두리, 종이 질감 |
| 글꼴 | 둥글고 굵은 한글 글꼴(예: 배민 주아체, 나눔스퀘어라운드 등, 상업용 라이선스 확인), 본문 최소 20px, 새싹 모드 24px 이상 |
| 아이콘 | 글자 없이도 뜻이 통하는 그림 아이콘 + 아래에 짧은 단어 1개 |

| 소리 | 버튼 효과음, 마스코트 음성(켜기/끄기 가능), 배경음은 기본 꺼짐 |

### 8.4 아이 UX 원칙
1. **글을 몰라도 쓸 수 있다:** 모든 버튼에 그림과 누르면 읽어 주는 음성. 입력은 말하기(음성) 또는 그림 고르기 우선, 키보드 입력은 부모용.
2. **큰 터치 영역:** 버튼 최소 64×64px(태블릿 기준), 버튼 사이 간격을 넉넉히, 드래그보다 탭 위주.
3. **한 화면에 한 가지 일:** 선택지는 한 번에 3~4개까지, 단계형 진행(1→2→3)과 진행 표시.
4. **실패가 없다:** 삭제처럼 되돌릴 수 없는 동작은 아이 화면에 없음. 모든 작업 자동 저장, "되돌리기" 버튼 항상 표시.
5. **기다림도 놀이:** AI 생성 대기 시간(삽화·3D)은 마스코트 미니 놀이·색칠·퀴즈로 채움.
6. **칭찬 중심:** 완성할 때마다 축하 연출과 스티커. 경쟁·순위·랭킹 없음.
7. **어른 기능은 숨김:** 결제, 주문, 설정, 공유는 **부모 잠금(9.4)** 뒤에 둠.

## 9. 접속 방식

### 9.1 계정 구조: 부모 계정 1개 + 아이 프로필 여러 개
```
부모 계정 (로그인·결제·동의의 주체, 만 14세 이상)
 ├─ 아이 프로필 A (닉네임, 나이, 아바타, 연령 모드)
 ├─ 아이 프로필 B
 └─ (기관) 반·모둠 프로필 — B2B 확장
```
- 아이는 **이메일·전화번호 없이** 부모 계정 안의 프로필로만 접속한다 (개인정보 최소 수집).
- OTT 서비스처럼 **"누가 볼까요?" 프로필 선택 화면**에서 자기 아바타를 눌러 들어간다.

### 9.2 접속 흐름
| 단계 | 누가 | 방법 |
|---|---|---|
| ① 가입 | 부모 | 카카오·네이버·구글·애플 간편 로그인 → **법정대리인 동의**(휴대폰 본인인증) → 아이 프로필 생성 |
| ② 기기 등록 | 부모 | 아이가 쓸 태블릿·폰에서 부모가 한 번 로그인하고 "아이용 기기로 등록" → 이후 이 기기는 로그인 유지 |
| ③ 아이 입장 | 아이 | 사이트/앱 실행 → 프로필 선택 화면 → 내 아바타 탭 → (선택) **그림 비밀번호** → 우리 집 책장 |
| ④ 부모 전환 | 부모 | 화면 구석 자물쇠 아이콘 → **부모 잠금** 통과 → 부모 모드 |

### 9.3 아이 로그인 방법 (부모가 선택)
| 방법 | 설명 | 추천 연령 |
|---|---|---|
| **아바타 탭** | 등록된 가족 기기에서는 아바타만 누르면 입장 | 3~5세 |
| **그림 비밀번호** | 동물·과일 그림 중 3개를 순서대로 누르기 (글자·숫자 몰라도 됨) | 5~8세 |
| **숫자 PIN 4자리** | 형제끼리 프로필을 구분해야 할 때 | 7세 이상 |
| **QR 코드 로그인** | 부모 폰에 뜬 QR을 아이 태블릿 카메라로 찍으면 입장 (새 기기, 학교·체험관 기기에서 편리) | 전 연령 |
| **반 코드 로그인 (B2B)** | 교사가 화면에 띄운 반 코드 입력 + 내 아바타 선택 | 유치원·초등 |

### 9.4 부모 잠금 (Parental Gate)
아이 화면에서 결제·주문·설정·공유·외부 링크로 가려면 반드시 통과해야 한다.
- 기본: **부모 PIN 4~6자리** 또는 기기 생체인증(Face ID·지문)
- 보조: 어른만 풀 수 있는 문제(예: 글자로 쓴 "삼십칠 더하기 사십팔은?") — 앱스토어 아동 카테고리 심사 기준 대응
- 3D 출력 주문은 아이가 **"갖고 싶어요" 요청**만 보낼 수 있고, 부모 폰으로 알림이 가서 부모가 승인·결제한다.

### 9.5 접속 경로
| 경로 | 설명 | 단계 |
|---|---|---|
| **웹 주소** | 예: toybook.co.kr 또는 book.wow3dpro.co.kr (도메인 확보 필요) | MVP |
| **PWA 홈 화면 설치** | 태블릿·폰 홈 화면에 앱 아이콘으로 추가, 전체화면 실행(주소창 없음 → 아이가 다른 사이트로 새지 않음) | MVP |
| **앱스토어 앱** | iOS·Android 앱 (아동 카테고리, 스크린 타임·패밀리 링크와 호환) | 정식 출시 |
| **wow3d pro 사이트 연결** | wow3dpro.co.kr에 "우리 아이 동화책 만들기" 메뉴·배너, 회원 계정 연동(SSO) 검토 | 베타 |
| **피규어 QR** | 배송된 피규어 받침대·포장의 QR을 찍으면 그 캐릭터의 책이 바로 열림 (실물 → 책으로 다시 연결) | 베타 |
| **기관 전용 링크** | 유치원·학교·도서관 전용 주소 + 반 코드 | 확장 |

### 9.6 기기 안전 설정
- PWA/앱은 **전체화면**으로 실행, 아이 화면에는 외부로 나가는 링크 없음.
- 아이 프로필은 부모가 정한 **하루 사용 시간**과 사용 가능 시간대(예: 오후 7~9시)를 따른다. 시간이 끝나면 마스코트가 "오늘은 여기까지!" 안내 후 책장으로 돌아감.
- 공용 기기(학교·체험관)는 일정 시간 사용하지 않으면 자동 로그아웃.
- 부모 대시보드에서 아이별 읽은 책, 사용 시간, 만든 캐릭터, "갖고 싶어요" 요청을 확인.

## 11. 기술 스택과 아키텍처

### 11.1 플랫폼 전략
**1차: 반응형 웹앱(PWA)** → **2차: 앱스토어 앱(Capacitor 또는 React Native 래핑)**

- 웹앱 하나로 PC·태블릿·모바일을 모두 지원해 개발 비용을 최소화.
- PWA로 홈 화면 설치, 오프라인 열람, 푸시 알림 가능.
- 앱스토어 배포가 필요해지면 같은 코드를 Capacitor로 감싸 iOS/Android 출시. (AR Quick Look, 카메라 등 네이티브 기능 활용)

### 11.2 기술 스택

| 영역 | 기술 | 이유 |
|---|---|---|
| 프론트엔드 | **Next.js (React) + TypeScript**, Tailwind CSS | SSR/PWA, 생태계, 개발 속도 |
| 책 편집기 | Konva.js 또는 Fabric.js (캔버스 레이아웃), Tiptap (텍스트) | 페이지 레이아웃·말풍선 편집 |
| e-book 뷰어 | 자체 뷰어(페이지 플립: StPageFlip), EPUB 내보내기: epub-gen 계열 | 고정 레이아웃 그림책 최적화 |
| 3D 뷰어 | **Three.js / React Three Fiber**, `<model-viewer>`(AR) | GLB 표시, AR 지원 |
| 백엔드 API | **NestJS (Node.js)** 또는 FastAPI | 주문·결제·사용자 관리 |
| AI 오케스트레이션 | Python 워커 (FastAPI + Celery/RQ, Redis 큐) | 생성 작업 비동기 처리 |
| 글 생성 | Claude API (동화체 한국어 품질, 안전성) | 나이별 문체 제어, 줄거리 구조화(JSON) |
| 삽화 생성 | 이미지 생성 API (예: Gemini 이미지, GPT 이미지, FLUX 계열) + 캐릭터 일관성용 레퍼런스 이미지 입력 | 품질·가격 비교 후 선택, 공급사 추상화 계층 |
| 객체 분리 | SAM 2 계열, 배경 제거 모델 | 클릭 기반 대상 선택 |
| 이미지→3D | **1차: Meshy 또는 Tripo API**, 2차: Hunyuan3D-2 / TRELLIS 자체 GPU 서버 | 초기엔 API로 빠르게, 규모 커지면 자체 호스팅으로 원가 절감 |

| DB | PostgreSQL (Supabase 또는 AWS RDS) | 사용자·책·주문 |
| 파일 저장 | S3 호환 스토리지 + CDN (CloudFront/Cloudflare R2) | 이미지·3D 파일 |
| 인증 | 카카오·네이버·구글·애플 로그인 | 국내 부모 사용자 |

### 11.3 시스템 구성도

```
[웹앱/PWA · 모바일앱]
   │  책 편집·뷰어·3D 뷰어·주문
   ▼
[API 서버 (NestJS)] ── PostgreSQL / S3
   │            │
   │            └─ 결제(PG) · 알림(FCM/알림톡)
   ▼
[작업 큐 (Redis)]
   ▼
[AI 워커 (Python)]
   ├─ 글 생성: LLM API
   ├─ 삽화 생성: 이미지 생성 API (캐릭터 카드 레퍼런스)
   ├─ 객체 분리: SAM
   ├─ 이미지→3D: Meshy/Tripo API 또는 자체 GPU
   └─ 출력 최적화: 메쉬 수리·받침대·STL/3MF·견적
   ▼
[wow3d pro 연동 어댑터]
   ├─ 1단계: 주문서+파일 전달(관리자 백오피스)
   └─ 2단계: 견적/주문 API + 상태 웹훅
   ▼
[wow3d 생산 (프린터·후가공·배송)]
```

### 11.4 핵심 데이터 모델 (요약)
- `User`(부모) 1:N `Child`(아이 프로필)
- `Book` (제목, 형식: 그림책/웹툰, 그림체, 소유자) 1:N `Page` (순서, 텍스트, 레이아웃 JSON)
- `Character` (캐릭터 카드: 외형 설명, 기준 이미지, 책/시리즈 연결)
- `Asset` (이미지/음성 파일, 생성 프롬프트, 출처: AI/업로드)
- `Model3D` (원본 이미지, GLB, 출력용 STL/3MF, 검사 결과, 상태)
- `Order` (Model3D, 옵션, 견적, 결제, wow3d pro 주문번호, 상태 이력)

## 15. 결정이 필요한 사항 (Open Questions)

1. **wow3d pro의 현재 시스템**: 주문 API나 관리자 화면이 있는지, 외부 앱 주문을 받을 수 있는 구조인지 (연동 1단계/2단계 결정)
2. **서비스명 확정**: 토이북 vs 꿈틀북 등, 상표 출원 여부
3. **출력 방식·가격**: 주력 출력 방식(FDM/레진/풀컬러)과 크기별 원가
4. **플랫폼 우선순위**: 웹앱 먼저(권장) vs 앱스토어 동시 출시
5. **개발 방식**: 내부 개발 / 외주 / 혼합, 예산 범위
6. **B2B 교육기관 시장**을 초기부터 함께 공략할지
7. **주 사용 연령대**: 3~5세(읽기 중심) vs 6~9세(만들기 중심) 중 MVP에서 어디에 먼저 집중할지
8. **도메인**: 독립 도메인(예: toybook.co.kr) vs wow3d pro 하위 주소(book.wow3dpro.co.kr)
